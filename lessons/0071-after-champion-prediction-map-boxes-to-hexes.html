After Champion Prediction Map Boxes To Hexes

After champion prediction, the next step is to turn boxes into board positions. The model tells you “champion is here.” The game logic needs “champion is on row 2, column 4.”

Win for this lesson: understand the first box-to-hex mapping rule before writing the script.

Do Not Skip The Gate

Move to hex mapping only if the champion detector is now good enough on board crops. If it still misses many champions, add more labeled examples first.

The Pipeline

board crop
  -> champion detector
  -> champion boxes
  -> one point per box
  -> nearest hex center
  -> occupied hex list

The Key Rule

Do not use the center of the champion box. Use the bottom-center point of the box, because the champion's feet/base are closer to the occupied hex than the head or body center. 

point_x = (x1 + x2) / 2
point_y = y2

Why Bottom-Center

box center:
  often lands on the champion body
  can be too high on tall units

bottom-center:
  lands near the champion base
  is closer to the board hex

Next Script

Create this file next:

scripts/map_champions_to_hexes.py

Script Job

  1. Load one image from outputs/board-crops.
  2. Run models/champion-detector.pt.
  3. Read each predicted champion box.
  4. Convert each box to bottom-center point.
  5. Get the 28 hex centers from create_board_hex_cells.
  6. Assign each champion point to the nearest hex center.
  7. Draw boxes, points, hexes, and row/column labels for review.

First Test Image

Use one board crop first. Do not batch all images until the overlay looks right.

Success Looks Like

green box:
  detected champion

yellow dot:
  bottom-center of champion box

red hex:
  chosen nearest hex

white text:
  row,column result

Decision

if dots land near the champion bases:
  implement nearest-hex assignment

if dots are too low or high:
  adjust the point rule

if boxes are missing champions:
  go back to labeling more data
