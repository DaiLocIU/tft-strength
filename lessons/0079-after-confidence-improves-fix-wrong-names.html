After Confidence Improves, Fix Wrong Names

Your champion names are better now. The next problem is different: some names are still wrong even when the model is confident. That needs a wrong-name review loop, not another broad low-confidence loop.

Win for this lesson: stop collecting random uncertainty, and start collecting the mistakes you can see in the final board output.

The New Rule

Low confidence finds uncertain crops. Wrong-name review finds visible mistakes. After the first active-learning pass, wrong-name review is usually more valuable.

Step 1: Run Combine On All Boards

cd /Users/inmac/Desktop/work-hard/tft-team-strength/vision-board-detector

.venv/bin/python scripts/combine_hex_signals.py --all \
  --champion-conf 0.65 \
  --identity-padding 0.08

Step 2: Review Final Images

Open these images and look for wrong champion names in the final overlay: 

outputs/combined-hex-signals/

Do not review every crop. Only write down examples where the displayed name is clearly wrong.

Step 3: For Each Wrong Name, Save The Crop

The training target should be the champion box crop, not the full board. Put the crop into the true class folder: 

data/champion-identity/labeled/<true_champion_name>/

If the crop is not a real champion, put it into: 

data/champion-identity/labeled/unknown/

Step 4: Fix Weak Classes First

Some classes still have very little data. These are high-risk classes: 

lux_(blossom): 1
lux_(elderwood): 2
lux_(lunar): 2
lux_(inferno): 5
lux_(solar): 5
training_dummy: 7
ahri: 8
kha'zix: 8
malphite: 8

If a wrong prediction involves one of these, add more examples for that class before tuning the model.

Step 5: Retrain Only After Useful New Labels

python3 scripts/split_champion_identity_dataset.py

yolo classify train \
  model=models/champion-identity-classifier.pt \
  data=data/champion-identity \
  imgsz=160 \
  epochs=50 \
  device=mps \
  project=runs/classify \
  name=champion-identity-wrong-name-fixes

Step 6: Add An Output Threshold

In the product output, do not trust every name. Use a threshold: 

identity_confidence >= 0.75 -> show champion name
identity_confidence <  0.75 -> show unknown / needs review

This turns model uncertainty into a controlled review queue instead of a wrong answer.

Retrieval Check

A. Keep reviewing every low-confidence crop forever.
B. Review visible wrong names and add targeted examples.
C. Add star detection before fixing wrong names.

Answer: B. Once the system mostly works, targeted error examples teach faster than broad loops.
