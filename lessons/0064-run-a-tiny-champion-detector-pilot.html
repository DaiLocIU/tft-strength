Run A Tiny Champion Detector Pilot

Do not label hundreds of champion boxes yet. First, run a tiny pilot to test whether champion boxes actually help your hex occupancy problem.

Goal: prove or reject the champion-detector idea with 10 to 15 carefully chosen board crops.

The Problem

You are right to worry about hidden champions. A champion box does not perfectly tell the standing hex. The detector is useful only if it helps remove obvious false occupied hexes or gives better object count. 

bad assumption:
  box bottom-center always gives correct hex

better assumption:
  box gives rough object evidence
  hex classifier still gives hex evidence
  code combines both

Do This Now

  1. Create a Label Studio project named champion-detector-pilot.
  2. Import only 10 to 15 board crop images.
  3. Use one class: champion.
  4. Choose hard images with Blue, Nunu, Kayle, Ivern, Elder Dragon, Maokai, and overlap.
  5. For each selected image, label every clearly visible player-side champion.
  6. Skip little legends, item effects alone, and champions mostly hidden.

How To Pick Images

Use images where the hex classifier made mistakes, because those are the cases this detector must help.

Label Rule

Draw one box around the visible body of each champion. The box may cross multiple hexes. 

label:
  one visible champion body = one box

skip:
  little legend
  item effect only
  less than half visible
  UI portraits and health bars as much as possible

Stop After The Pilot

After 10 to 15 images, stop labeling and train a small detector. Then test predictions on the same hard images. 

continue if:
  detector finds most champion bodies
  detector ignores little legends/effects
  detector gives useful object count

stop if:
  boxes are chaotic
  hidden champions cannot be found
  detector confuses UI/effects too much

The Real Decision

If the pilot works, label 50 more. If it fails, do not force it. Move to a different signal, such as a standing-point/keypoint label or better hex geometry/crop evidence.
