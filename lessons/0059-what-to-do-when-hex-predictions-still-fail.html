What To Do When Hex Predictions Still Fail

If predict_hex_occupancy is still wrong, do not blindly label forever. First decide what kind of wrong result you are seeing.

Current corrected labels: 1218 occupied and 3598 empty.

The Short Answer

Yes, the main loop is still label and retrain. But only do that when the mistake is a visual example problem. If the same failure returns again and again, it may be a code or model-design problem. 

good loop:
  find mistakes
  label those exact mistakes
  rebuild split
  retrain
  predict again

Three Kinds Of Wrong

Before retraining, sort each wrong image into one of these buckets.

data problem:
  label is wrong or missing
  fix labels, then retrain

threshold problem:
  prediction is low confidence or borderline
  adjust confidence rule or mark uncertain

model-design problem:
  crop does not contain enough information
  change crop, add context, or detect unit anchor instead

When Labeling Helps

Labeling helps when the model has not seen enough examples of a visual pattern: item effects, flying champions, shadows, dark arena colors, big champions overlapping neighbors, or partial body crops. 

label more if:
  the crop shows useful visual evidence
  a human can decide from the crop
  the mistake type appears in only some examples

When Labeling Is Not Enough

If a human cannot tell from the crop alone, the classifier also cannot reliably learn it. Then the next fix is code or model design. 

change design if:
  crop is too small
  champion body belongs to neighbor hex
  standing point is outside the crop
  shadow is the only reliable signal
  same false positive returns after retraining

The Next Practical Step

Create a new mistake list only for the current model, relabel those images, rebuild the split, retrain one version, and compare. Do not mix old mistake lists with new ones unless they still fail. 

data/hex-occupancy/mistakes/v3-wrong.txt

then:
  open http://localhost:8091/?queue=v3-wrong
  relabel only those boards
  rebuild split
  train v4
  predict all again

Stop Rule

If the same mistake type survives two focused retrains, stop adding more random labels. Then change one design variable and test again. 

possible design changes:
  larger crop around each hex
  lower/higher occupied threshold
  save uncertain predictions for review
  classify with neighbor context
  detect champion foot/shadow anchor

Recall

  • When does labeling more help?
  • When should you change the code instead?
  • Why keep a separate mistake list for each model version?
